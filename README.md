# PD Impression — High Sierra 兼容测试版

本目录属于 `compat/high-sierra`，目标为 2011 年 Intel iMac、macOS 10.13.6、8GB 内存。原版保留在 `main`。兼容版应用名为 **PD Impression High Sierra**，设置与缓存独立。当前版本为 **0.1.0-hs.1**；Windows 上验证成功不等于已在 High Sierra 上运行。构建与实机验收见 [Mac 测试说明](docs/MAC-INTEL-TEST.md)。

离线胶卷索引图桌面应用。以 React 和 TypeScript 制作界面，通过 Electron 独立处理进程调用 Sharp／libvips 读取 TIFF、生成预览和导出 JPEG。

GitHub 项目名：FilmContactSheet — auto-generating contact sheets from scanned film rolls.

当前为 **0.1.0-hs.1 兼容开发预览版**，支持 11 种扫描类型及多项目处理。完整产品需求见同目录的《胶卷索引应用第一版需求文档.md》，现有界面参考图保存在 `assets/main-interface-v1.png`。开发预览版不等于完整 V1.0 已交付。

## 启动

Windows 可双击 `start-pdimpression.cmd`，使用已经安装的本地依赖与构建结果运行。移动项目时要连同必要运行文件保留；这不是独立安装包。

开发环境使用 Node.js 24 LTS 或满足锁定依赖要求的更新版本。首次安装依赖需要联网，安装后的应用处理照片不需要联网。

```powershell
npm.cmd ci
node node_modules/electron/install.js
npm.cmd run dev
```

正式构建及本地预览：

```powershell
npm.cmd run build
npm.cmd start
```

macOS 使用 `npm` 而不是 `npm.cmd`，在 Mac 上重新安装依赖，不复制 Windows 的 `node_modules`。最终 Mac 芯片、系统版本与真实扫描文件仍需实机验证。

## 已实现

- TIFF 和 JPEG 文件／文件夹导入、文件名自然排序、原图尺寸及 ICC 状态读取。
- 多项目工作区：左侧项目目录、预览上方的项目标签；单击切换，双击名称重命名，点叉关闭。每卷独立保留照片、模板、缩放、选中项、撤销记录及保存路径。
- 导入、导出在后台处理：每个任务绑定所属项目，导入一卷时可切换或新建另一卷继续导入。项目目录和标签显示各自进度，任务入口位于底部导入提示栏，展开后任务在原栏中间单行横向排列，超出时横向滚动，展开和收起高度一致、不遮挡操作区；导入完成及导入／导出取消提示在 2 秒后自动移除；导出完成保留文件夹入口，所有任务结束 4 秒后自动收起。支持逐个取消、查看完成／失败和打开导出文件夹。图片任务最多一个运行，其余排队；界面仍可切换和编辑其他项目。
- 导出使用提交时的项目快照；开始后关闭导出设置窗口，允许继续编辑或处理其他项目。正在导入的项目暂时锁定编辑，其他项目可用；有未结束任务的项目需先完成或取消任务再关闭。任务队列暂不跨应用重启恢复。
- 默认名称使用当前打开项目中最小的可用编号：关闭或重命名“未命名项目 1”后，下次可再次使用 1；只要 1 仍被占用才使用 2。编号不记录到缓存，也不扫描磁盘文件；保存时仍由用户选择文件名。
- 项目名称随项目文件保存；关闭未保存的项目可取消、放弃修改或保存并关闭，关闭标签不会删除磁盘文件。启动和关闭最后一个标签后，项目目录为空、标签栏隐藏，中心显示扫描类型选择；选择类型或打开项目后才出现项目。
- 先选扫描类型，再导入文件或文件夹；每个项目保存自己的扫描类型和模板。
- 类型选择区左侧为单张、右侧为整条。120 模板使用无齿孔黑色片边，135、半格与 XPan 保留装饰齿孔；既有画格比例及位置保持不变。整条 TIFF 每份占一行，完整保留，不自动切分、不推算内部照片数量；新增整条超出预留行数时自动增加行数。
- 新模板使用下表的无单位扫描比例，图片完整适配画格，不拉伸、不裁切。页面继续采用 A 系列比例，创建项目时按模板预留三行备注及 Logo 的空间；默认 0.5mm 条间白缝。
- 已有 135 项目保持原版 42 格、6 列 7 行、36×24mm 画格和 35mm 条高，重新打开不会自动迁移排版。
- 末尾整条空白胶片隐藏；38 张时保留末尾两张与四个黑格。
- 拖动换序、旋转、替换／单文件重新定位、设为空位、插空位、移除并前移、撤销与重做。
- 卷号、胶卷型号、日期、备注和部分模板参数编辑。
- 固定使用 `pics/logo.jpg`：宽 30mm，放在页面右下角的页边距内，跟随右页边距与底部留白；暗房模板不再提供 Logo 上传、移除或位置设置。
- JSON 项目文件保存及重开，使用相对原图路径和模板快照；不复制原 TIFF。旧项目中的 Logo 设置自动忽略。
- 独立 Electron utilityProcess 生成预览与导出，进度及取消。
- 只提供高清交付：从原图生成 sRGB JPEG，带 ICC 和物理分辨率信息。单张上限 25,000,000 字节；优先保持质量 94，超限时保持像素尺寸并自动降低 JPEG 质量，不再提供 2400px 便捷预览版。
- 失败文件、超容量、布局溢出、缺失原图和输出重名提示。
- 导出窗口支持自定义文件名、最终名称预览和恢复默认命名；中文名称可用，自动补 `.jpg`，重名成品保留覆盖确认，原图禁止覆盖。

## 扫描类型和默认排版

以下比例由暗房提供，顺序为**高 : 宽**，不是厘米或毫米。模板在打印页面中的尺寸是排版尺寸，不能据此推断底片实测尺寸。参数集中在 `src/shared/scan-types.ts`。

| 类型 | 高 : 宽 | 单张容量／整条预留 |
| --- | --- | --- |
| 135 | 2.48 : 3.69 | 6 列 × 7 行，42 格 |
| 135 整条 | 2.48 : 22.59 | 7 条，可随导入增加 |
| 半格 | 2.48 : 1.83 | 12 列 × 7 行，84 格 |
| 6×7 | 5.64 : 7.11 | 3 列 × 4 行，12 格 |
| 6×7 整条 | 5.64 : 22.15 | 4 条，可随导入增加 |
| 6×6 | 5.64 : 5.64 | 3 列 × 4 行，12 格 |
| 6×6 整条 | 5.64 : 18.15 | 4 条，可随导入增加 |
| XPan | 2.42 : 6.59 | 3 列 × 7 行，21 格 |
| XPan 整条 | 2.42 : 19.77 | 7 条，可随导入增加 |
| 6×4.5 | 5.6 : 4.16 | 4 列 × 4 行，16 格 |
| 6×4.5 整条 | 5.6 : 19.22 | 4 条，可随导入增加 |

导入时按画格的横／竖方向选择朝向，之后可以手动旋转。备注固定在完整模板最后一行下方，不随隐藏空行而上移；字号 3.5mm、间隔 3mm、行距 5mm、颜色 `#333333`。

扫描类型在新建项目时确定，打开项目时自动恢复；需要另一种类型时新建项目。整条文件超过预留数量会扩大页面，页面宽度上限仍为 600mm，超出可排范围时明确提示，不会自动压缩长宽比或截断内容。

## 开发预览版的边界

- 新增扫描模板已用生成的 TIFF 验证；暗房实际扫描样本、内含黑边和不同朝向仍需核对。整条 TIFF 不识别或裁掉文件中已有的边框。
- 照片使用单击选中，保留列表缩略图、成品预览和右侧照片信息；不提供双击预览弹窗。
- 复杂信息区布局、字段自由排序、Logo 偏移与页脚位置、主体垂直对齐、完整文字碰撞检测尚未实现。
- 文字使用系统字体，尚未完成可分发字体统一；Mac 与 Windows 文字布局必须后续核对。
- 导出默认 8000px 宽、可选 6000／10000px，为初始性能档位，不是对真实扫描文件的性能承诺。
- 无 ICC 的普通 RGB／灰度输入先提示，导出要求用户确认按 sRGB／灰度解释；未知无配置色彩空间拒绝处理。
- 单图解码上限 1.5 亿像素，多页 TIFF 明确拒绝；需要据真实扫描样本调整并验证。
- 导入任务当前完成本次文件批次后统一展示缩略图，处理中会显示逐文件进度。
- 原图丢失可逐张定位，批量重新定位文件夹和缓存清理管理界面尚未实现。
- 退出有未保存内容时可返回保存或放弃退出，尚未做带原生“保存并退出”的完整三按钮流程。
- Windows 安装包未签名；Intel Mac 测试版使用 ad-hoc 签名，未配置 Apple Developer ID 和公证。High Sierra 10.13.6 仍需目标电脑实测；Mac 安装包尚需在 Intel Mac 构建。
- 软件不自动更新，不上报照片或项目数据。

## 目录

固定 Logo 的源文件是 `pics/logo.jpg`，构建时同时内嵌到预览和导出程序。更换该文件后重新构建即可，不需要通过界面上传。位置、尺寸及胶片整体上移量集中在 `src/shared/branding.ts`；当前胶片偏移为 -20mm，比上一版再上移 10mm，条间白缝与画格尺寸保持原值。

```text
src/shared    项目模型、参数校验、毫米布局与 SVG 版式
src/main      Electron 文件操作、图片任务协调、Sharp 处理进程
src/preload   隔离的界面与本地能力桥接
src/renderer  React 工作台和样式
tests         排版与图片处理测试
scripts       实际桌面流程测试
assets        已确认的设计参考
```

原图像素不通过界面进程传输。预览是缩小的 JPEG 数据，正式导出重新读取 TIFF；所有图片任务逐张处理，Sharp 内部并发限定为 1、缓存上限 48MB（不代表整个进程的内存上限）。整图导出仍会占用与输出像素相关的内存，需要目标 Mac 实测。

## 打包

```powershell
npm.cmd run pack:win
npm.cmd run dist:win
```

Intel Mac 构建使用支持 Node.js 24 的较新 Intel Mac；旧 iMac 只负责运行最终应用。进入源码目录后执行：

```sh
bash build-high-sierra.command
```

脚本安装锁定依赖、执行测试、构建 DMG、验证签名和所有 Mach-O 的最低系统版本、测试打包应用，并生成 SHA256 校验文件。输出为 `release/PD-Impression-0.1.0-hs.1-High-Sierra-Intel.dmg`。Windows 上的 electron-builder 不支持生成 Mac 应用；源码 ZIP 是构建材料，不是安装包。

GitHub Actions 的 **Build High Sierra Intel test installer** 工作流仅手动触发，构建命令禁用发布；本次没有推送或执行工作流。若以后选择云端构建，仍需要另行授权推送。较新 Mac 上的检查不能代替 10.13.6 实机验收。

运行环境锁定 Electron 26.6.10（Node.js 18.16.1、Chromium 116）、Sharp 0.32.6／libvips 8.14.5。开发工具继续使用 Node.js 24，输出分别面向 Node 18 和 Chromium 116。

Electron 26 已停止维护。2026-11-25 的 `npm audit --omit=dev` 报告 Sharp 运行依赖存在 high 风险项，因此这是用于可信本地扫描文件的旧机兼容测试版，不能宣称安全问题已解决。不要用 `npm audit fix --force` 自动升级，否则会失去旧系统兼容性。具体依据与限制见 Mac 测试说明。
